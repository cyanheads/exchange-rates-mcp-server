# 0.6.0 — 2026-11-02

## Added

- Add `skill://exchange-rates-guide/SKILL.md` for historical FX coverage, paging and SQL analysis.
- **`fx_list_currencies.include_retired`** discovers historical codes with optional official ECB coverage outer bounds; discovery discloses unavailable metadata, and coverage dates do not guarantee uninterrupted observations. [#38](https://github.com/cyanheads/exchange-rates-mcp-server/issues/38)
- **`fx_get_timeseries.limit`** bounds previews at 500 observations and accepts 0 for summary-only results; counts, summary and complete staged tables remain independent of delivery size. [#37](https://github.com/cyanheads/exchange-rates-mcp-server/issues/37)

## Changed

- **`fx_dataframe_query`** now rejects previously correct unqualified user-column and CTE references named `current_schema` with `invalid_query` after framework adoption; qualify the reference as `t.current_schema`.
- **V1 requests** share a 12-second deadline across retries; optional official metadata uses one 1-second request without retries and never gates successful rate calls.

## Fixed

- **Time-series coverage** reports the count and bounds of served days missing either currency leg, composing coverage and delivery notices while summarizing observed days only. [#34](https://github.com/cyanheads/exchange-rates-mcp-server/issues/34)
- **`upstream_no_data`** preserves the offending `field` and sorted, deduplicated `missing_codes` from served snapshots without attributing generic 404 failures. [#35](https://github.com/cyanheads/exchange-rates-mcp-server/issues/35)
- **`fx_convert_currency`** preserves the unrounded JavaScript-number product and formats rates in quote units per base unit. [#36](https://github.com/cyanheads/exchange-rates-mcp-server/issues/36)
- **Startup configuration** normalizes blank and placeholder canvas settings, honors dotenv configuration and reports invalid framework configuration through the startup error boundary.
- **Plugin and MCPB packaging** adds Agent Plugins manifests, includes published skills, preserves SDK runtime skill modules and removes development/build artifacts; development guidance and packaging checks are synchronized.
