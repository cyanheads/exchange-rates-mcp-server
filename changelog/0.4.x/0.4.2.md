# 0.4.2 — 2026-10-04

Advertised tool schemas are unchanged: `tools/list` (names, input/output schemas, annotations, descriptions) is byte-identical to 0.4.1.

## Changed

- **Tool error results carry `data.requestId`** and close with `request <id>`, and a declared `errors[]` recovery hint reaches the result without a `ctx.recoveryFor` forward (0.13.10). The tools drop those forwards; the hints callers receive are unchanged.
- **Server stack traces (0.13.7) and request-context fields (0.13.8) no longer reach client-facing error `data`.**
- **Argument repair and rejections** — a JSON-stringified object, or an integer sent for a string field, is repaired instead of rejected, and argument rejections name the field paths involved (0.13.9).
- **`ctx.log` notifications to the client honor `MCP_LOG_LEVEL` and mask sensitive fields** (0.13.11).
- **DataCanvas scratch files live in a private per-process directory**, and `CANVAS_TEMP_PATH` now names its parent (0.13.9).
- **Dockerfile** — production dependencies cross-install (`--os`/`--cpu`) in a `deps` stage on `$BUILDPLATFORM`, OTel peers through `scripts/install-otel.ts`, so multi-arch builds never run Bun under emulation (0.13.10); `scripts/prune-musl-packages.ts` drops musl-only packages (0.13.11). Base images move to `oven/bun:1.4.2` (0.13.7).
- **Config docs** — `.env.example` and the README document `MCP_REQUEST_STATE_KEY` (no tool here returns `requestState`), `LOG_TOOL_FAILURE_PAYLOADS` / `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES`, and the OTLP endpoints, log export opt-in through `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`; `.env.example` adds the log rate-limit vars.
- **Repo hygiene** — `.gitignore` and `.dockerignore` cover every `.env*` variant, `.dockerignore` excludes the MCP Registry token files, `.mcpbignore` drops `docs/idea.md`, `logs/`, and `.cache/` from the bundle, npm `files` excludes `dist/*.mcpb`, and `packageManager` moves to `bun@1.4.2`.
- **CodeQL workflow** runs one matrix job per language, uploading under `/language:<language>` so alerts raised by default setup close here once fixed.
- **Framework skills and dev scripts** (`devcheck`, `lint-mcp`, `lint-packaging`, `check-skill-versions`, `release-github`) resynced to mcp-ts-core 0.13.11; `CLAUDE.md`/`AGENTS.md` now declare gated release PRs.

## Removed

- **`MCP_FORCE_CONSOLE_LOGGING`** is gone from the Dockerfile; nothing read it (0.13.8).

## Fixed

- **`fx_get_timeseries` stages a spilled series with `rate` typed `DOUBLE`** ([#21](https://github.com/cyanheads/exchange-rates-mcp-server/issues/21)) — `spillover()` gets an explicit column schema, so a series whose leading rates are whole numbers no longer stages `rate` as `BIGINT` and truncates later fractional rates.
- **`server.json` npm entries** drop the `run start:*` package arguments a registry client would hand the bin and set `runtimeHint: "npx"`; the `streamable-http` entry fixes `MCP_TRANSPORT_TYPE` to `"value": "http"` so it actually starts HTTP (0.13.11).
- **`FX_ENABLE_CANVAS_DROP` docs** ([#23](https://github.com/cyanheads/exchange-rates-mcp-server/issues/23)) — `server.json` and the README said a disabled `fx_dataframe_drop` stays listed but uncallable; it is absent from `tools/list` until the flag is `true`, and the descriptions now say so.
