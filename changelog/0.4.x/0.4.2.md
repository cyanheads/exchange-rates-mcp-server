# 0.4.2 — 2026-10-04

Advertised tool schemas are unchanged: `tools/list` (names, input/output schemas, annotations, descriptions) is byte-identical to 0.4.1.

## Changed

- **Tool error results carry `data.requestId`**, their text closes with `request <id>`, and a declared `errors[]` recovery hint reaches the result without a per-site `ctx.recoveryFor` forward (0.13.10). The tools drop those forwards; the hints callers receive are unchanged, and `tests/tools/fx-recovery-hints.test.ts` asserts each one on the wire.
- **Server stack traces (0.13.7) and request-context fields (0.13.8) no longer reach client-facing error `data`.**
- **Argument repair and rejections** — a JSON-stringified object, or an integer sent for a string field, is repaired before argument validation, and argument rejections name the field paths involved (0.13.9).
- **`ctx.log` notifications to the client honor `MCP_LOG_LEVEL` and mask sensitive fields** (0.13.11).
- **DataCanvas scratch files live in a private per-process directory**, and `CANVAS_TEMP_PATH` now names its parent (0.13.9).
- **Dockerfile** — dependencies install in a `deps` stage on `$BUILDPLATFORM` with a cross-install through `scripts/install-otel.ts` (0.13.10 scaffold), so multi-arch builds never run Bun under emulation; musl-only packages are pruned from the image by `scripts/prune-musl-packages.ts` (0.13.11); base images move to `oven/bun:1.4.2` (0.13.7).
- **Config docs** — `.env.example` and the README configuration table document `MCP_REQUEST_STATE_KEY` (inert here: no tool returns `requestState`), the opt-in `LOG_TOOL_FAILURE_PAYLOADS` / `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES`, and the OTLP endpoints, where log export stays off unless `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` is set; `.env.example` also lists the log rate-limit vars and the per-signal trace/metric endpoint overrides.
- **Repo hygiene** — `.gitignore` and `.dockerignore` cover every `.env*` variant (`.env.example` stays tracked), `.dockerignore` excludes the MCP Registry token files, `.mcpbignore` keeps `docs/idea.md`, `logs/`, and `.cache/` out of the bundle, the npm `files` list excludes `dist/*.mcpb`, and `packageManager` moves to `bun@1.4.2`.
- **CodeQL workflow** runs one matrix job per language, uploading under `/language:<language>` so alerts raised by default setup close here once fixed.
- **Framework skills and dev scripts** (`devcheck`, `lint-mcp`, `lint-packaging`, `check-skill-versions`, `release-github`) resynced to mcp-ts-core 0.13.11; `CLAUDE.md`/`AGENTS.md` now declare gated release PRs.

## Removed

- **`MCP_FORCE_CONSOLE_LOGGING`** is gone from the Dockerfile; nothing read it (0.13.8).

## Fixed

- **`fx_get_timeseries` stages a spilled series with `rate` typed `DOUBLE`** ([#21](https://github.com/cyanheads/exchange-rates-mcp-server/issues/21)). `spillover()` now receives an explicit column schema; previously a series whose leading rates were whole numbers was sniffed as `BIGINT`, and the appender silently truncated later fractional rates.
- **`server.json` npm entries** drop the `run start:*` package arguments a registry client would hand the bin and set `runtimeHint: "npx"`; the `streamable-http` entry fixes `MCP_TRANSPORT_TYPE` to `"value": "http"` so it actually starts HTTP (0.13.11).
