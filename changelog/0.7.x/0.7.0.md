# 0.7.0 — 2026-11-16

## Added

- **`fx_get_timeseries.stage`** (default `false`): `true` stages even a short series on a new canvas, and its `canvas_id` stages the next series beside it. An unknown `canvas_id` now returns the tool's declared `canvas_not_found` recovery, which names `stage: true`, instead of the registry's generic hint. [#41](https://github.com/cyanheads/exchange-rates-mcp-server/issues/41)
- **`fx_list_currencies`** rows carry `retired`; rows `include_retired` appends are `retired: true` and render ` · retired`. `fx://currencies` stays current-only. [#42](https://github.com/cyanheads/exchange-rates-mcp-server/issues/42)

## Changed

- `fx_dataframe_query` refuses every statement naming a DuckDB `pragma_*` table function (`pragma_collations`, `pragma_database_size`, `pragma_metadata_info`, `pragma_platform`, `pragma_show`, `pragma_storage_info`, `pragma_table_info`, `pragma_user_agent`, `pragma_version`) — quoted in any case, bare or `main.`/`system.main.`-qualified, or unquoted after a string literal or comment — even where the plan never runs it: under `LIMIT 0` or `WHERE false`, in an unreferenced CTE, a `UNION ALL` branch under `LIMIT 0`, a `LEFT JOIN … ON false`, a `LIMIT 0` scalar or `IN` subquery, `EXISTS` under `false`, or inside a `query()` string. 0.6.0 answered these from the staged tables; they now fail `invalid_query` (mcp-ts-core 0.13.19).
- **`upstream_no_data`** carries `currency_windows` plus one sentence per code placing the requested date or range against its ECB coverage bounds (coverage begins, coverage ends, or inside bounds that can contain gaps) when ECB coverage metadata is available. Its `when` and recovery text are new. [#44](https://github.com/cyanheads/exchange-rates-mcp-server/issues/44)
- **`fx_dataframe_query`** forwards the SQL gate's own recovery hint, followed by "fx_dataframe_describe lists the staged tables and their columns." Previously every refusal said "Run fx_dataframe_describe first…".
- **Upstream error bodies** no longer reach the client error envelope (mcp-ts-core 0.13.22).
- **The SQL gate** now answers `range()` and `generate_series()` with constant arguments, and no longer refuses denied names inside nested comments or `$$`/`$tag$`/`E''` literals (mcp-ts-core 0.13.19–0.13.22).
- **A missing table** in `DESCRIBE`/`SHOW`/`SUMMARIZE`/`TABLE` now fails `missing_table`, and a path-named `FROM` fails `invalid_query` (mcp-ts-core 0.13.19–0.13.22).
- **`skill://exchange-rates-guide/SKILL.md`** (1.1): Compare series opens with `stage: true`, and Identifiers points at `retired` and `currency_windows`.

## Fixed

- **`date_snapped` and the snap note** name all three causes — a weekend, a TARGET holiday, or the day's fix not yet published — and the `fx_get_timeseries` empty-window notice names a fix not yet published. [#40](https://github.com/cyanheads/exchange-rates-mcp-server/issues/40)
- **`fx_list_currencies` `as_of`** is read uncached on every call from the `/latest?base=EUR` request a latest-rate call makes, so it matches that call's `rate_date`. A failed `/latest` read now fails discovery rather than reporting an earlier cached date. [#43](https://github.com/cyanheads/exchange-rates-mcp-server/issues/43)
- **`fx_get_timeseries`** no longer acquires a canvas for a series that fits the inline preview. At the tenant canvas cap, an inline-fit range over 90 days now answers inline instead of failing `canvas_capacity_exhausted` (lazy acquisition is pending in cyanheads/mcp-ts-core#501).
- **`fx_get_timeseries`** with DataCanvas off fails explicit staging (`canvas_id` or `stage: true`) with `canvas_unavailable` before any Frankfurter request.
- **`fx_dataframe_query` `row_limit`** clamps to the configured `CANVAS_DEFAULT_ROW_LIMIT` (10,000 by default), read per call. A lowered cap previously failed `invalid_query`, and a raised one was still held to 10,000.
- **A 200 v1 response that is not JSON** (an HTML interstitial) fails as a serialization error with no retry. It used to fail `-32007` after three attempts.
- **A failed ECB-metadata read** is retried after five minutes instead of being cached for a day; successful reads are still cached for a day.
- **The `upstream_no_data` fallback messages** on the four rate tools name the trimmed, uppercased codes, so a padded `" ils "` no longer prints as "no  ils /eur rate". The message for `date: 'latest'` says "the latest published date".
- **README** provenance line no longer claims `rate_date` and `date_snapped` on every response.
