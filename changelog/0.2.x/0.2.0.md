# 0.2.0 — 2026-07-31

## Added

- **`fx_get_timeseries` `notice` enrichment** — a success-path `ctx.enrich.notice()` explains an empty `rates` map (the range covers only non-publication days) or a long range that stayed inline because `CANVAS_PROVIDER_TYPE` isn't set, so a legitimate empty/inline result doesn't read as a failure.
- **`disabledTool()` gating** — `fx_dataframe_describe` and `fx_dataframe_query` are skipped from `tools/list` when DataCanvas isn't configured; they stay visible as disabled cards (hinting `CANVAS_PROVIDER_TYPE=duckdb`) on the HTML landing page and server manifest. ([#7](https://github.com/cyanheads/exchange-rates-mcp-server/issues/7))
- **Structured Frankfurter service errors** — `src/services/frankfurter/errors.ts` stamps `invalid_date_format`, `unsupported_currency`, and `upstream_no_data` reasons onto `McpError.data`; tool handlers read them via `failureOf()` instead of matching on error-message prose.
- **`fx_dataframe_query` `missing_table` error contract** — a query against a table not staged on the canvas (or evicted by TTL) now surfaces its own reason instead of falling through to `invalid_query`.

## Changed

- **`fx_convert_currency.amount` rejects non-positive values** — schema gains `.positive()`; zero and negative amounts are now rejected at parse time instead of silently converting. **Breaking**: a client that relied on converting a zero or negative amount must change its input. ([#5](https://github.com/cyanheads/exchange-rates-mcp-server/issues/5))
- **Date validation runs before range/currency checks** — `fx_get_rate`, `fx_get_rates`, `fx_get_timeseries`, and `fx_convert_currency` validate `YYYY-MM-DD` shape and calendar validity (new `isIsoDate()`) before any lexicographic range comparison or upstream call, surfacing a new `invalid_date_format` reason instead of misclassifying a malformed date as `unsupported_currency` or `invalid_range`. ([#4](https://github.com/cyanheads/exchange-rates-mcp-server/issues/4))
- **Same-currency identity handling extended** — `fx_get_rate` (already identity-aware) now dates its `rate: 1` result to the ECB's real publication day for that currency, via a proxy quote, instead of always `today`; `fx_get_timeseries` and `fx_get_rates` gain the same identity path, returning `rate: 1` per publication day or for a base-in-`symbols` request instead of surfacing Frankfurter's upstream 422. ([#6](https://github.com/cyanheads/exchange-rates-mcp-server/issues/6))
- **`fx_get_rates` misattributed `unsupported_currency`** — an invalid entry in `symbols` now names the offending currency instead of always blaming `base_currency`. ([#8](https://github.com/cyanheads/exchange-rates-mcp-server/issues/8))
- **`fx_dataframe_query` cancelled queries** — an aborted query (`ctx.signal`) is no longer misclassified as `invalid_query`; it now propagates as the framework's own Timeout instead of matching the SQL-gate's error-message check.
- **Currency codes checked against a live, day-cached ECB set** (`FrankfurterService.currencies()`) before any request, replacing the old regex format guard — an unsupported code is now named specifically instead of surfacing a generic upstream 404.
- **Template-lag adoption** — `bunfig.toml` (Socket install scanner + a 3-day `minimumReleaseAge` supply-chain guard, framework excluded), `Dockerfile` (`--ignore-scripts`, `--omit=dev` on the OTel install layer, BuildKit cache mounts, pinned `oven/bun:1.3.14` base images), `.gitignore` (`data/` → `/data/`, root-scoped only), `devcheck.config.json` (scanner added to the depcheck ignore list; `outdated.allowlist` cleared), `.env.example` (documents `CANVAS_TEMP_PATH`), new `.gitattributes`, `.github/SECURITY.md`, `.github/FUNDING.yml`; 19 framework skill files re-synced to the installed `mcp-ts-core` version.

## Fixed

- **`fx_get_timeseries` no longer returns dates outside the requested range** — Frankfurter's snap-to-prior-business-day on a weekend/holiday-opening range is now clipped: rows outside `[start_date, end_date]` are dropped, and a range covering only non-publication days returns an empty `rates` map with `rate_count: 0` plus an explanatory `notice` instead of a rate from before the requested window. ([#3](https://github.com/cyanheads/exchange-rates-mcp-server/issues/3))
- **`getTimeSeries()` no longer fabricates a `0` rate** for a day the quoted currency is missing from the upstream response — the row is dropped instead of reading as a real (and wrong) ECB rate.
